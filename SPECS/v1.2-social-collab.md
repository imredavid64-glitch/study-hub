# v1.2 Specification — Social & Collaboration

## Overview
Add real-time social layer: study groups, shared resources, peer review, and deeper LearningFans integration. All features work offline-first; sync when online.

---

## 1. Study Groups

### Data Model (Supabase)
```sql
CREATE TABLE study_groups (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  description TEXT,
  owner_id UUID REFERENCES users(id),
  invite_code TEXT UNIQUE NOT NULL,
  is_public BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE group_members (
  group_id UUID REFERENCES study_groups(id) ON DELETE CASCADE,
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  role TEXT CHECK (role IN ('owner','admin','member')) DEFAULT 'member',
  joined_at TIMESTAMPTZ DEFAULT now(),
  PRIMARY KEY (group_id, user_id)
);

CREATE TABLE group_resources (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id UUID REFERENCES study_groups(id) ON DELETE CASCADE,
  owner_id UUID REFERENCES users(id),
  type TEXT CHECK (type IN ('notes','flashcards','study-guide','quiz','link')),
  title TEXT NOT NULL,
  content JSONB,
  is_pinned BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

### RLS Policies
- `group_members`: user can read own memberships; owners/admins read all
- `study_groups`: members can read; owners/admins write
- `group_resources`: members read; owners/admins/creator write

### UI: New "Groups" Tab
- **My Groups** — list with role badges, unread indicators
- **Discover** — public groups by subject, activity, size
- **Create Group** — name, description, subject tags, public/private
- **Group Detail** — tabs: Feed, Resources, Members, Sessions, Analytics

### Group Feed (Real-time)
- Activity stream: new resources, session completions, achievements
- Comments/reactions on posts
- Mentions (@name) with notifications
- Pagination + infinite scroll

## 2. Shared Sessions (Synchronized Pomodoro)

### Architecture
- WebRTC mesh (max 8) or SFU for larger groups
- Signaling via Supabase Realtime (ephemeral channel per session)
- Local-first: timer runs locally; sync state (phase, time remaining, participants)

### Session Flow
1. **Host creates** → generates session code (6-char)
2. **Members join** via code or group invite
3. **Host starts** → all timers sync to same phase
4. **Real-time presence** — avatar + status (focus/break/away)
5. **Chat overlay** — ephemeral messages during breaks
6. **End** → summary saved to each member's analytics + group feed

### Offline Behavior
- Timer continues locally
- On reconnect: merge session log, resolve conflicts (last-write-wins for timer state)

## 3. Peer Review System

### Flashcard/Note Swaps
- **Create Review Request** — select deck/note, set due date, add context
- **Matchmaking** — algorithm: same subject, similar level, reciprocal history
- **Review Interface** — side-by-side: original + reviewer annotations
- **Rating** — 1-5 stars + written feedback
- **Reputation** — reviewer score based on helpfulness votes

### Study Guide Co-creation
- Fork existing guide → edit → propose merge
- Diff view with accept/reject per section
- Credit graph (contributors with % contribution)

## 4. LearningFans Deep Integration

### OAuth Link
- "Connect LearningFans" in Settings → OAuth flow
- Store encrypted tokens in `users.lf_tokens` (service-key write only)
- Sync: profile, spaces, notifications bidirectional

### Unified Spaces Tab
- Embedded iframe (sandboxed) for LearningFans spaces
- PostMessage bridge: navigate, share content, auth state
- Deep links: `studyhub://learningfans/space/{id}`

### Cross-Platform Notifications
- Webhook from LF → push to Study Hub (service worker)
- Unified inbox tab with source badges
- Mark-read syncs both ways

## 6. Notification System

### Channels
- **In-app** — bell icon, unified inbox (persisted)
- **Push** — Web Push API (VAPID keys in Vercel env)
- **Email** — digest (daily/weekly), opt-in per category

### Categories
| Category | Default | Channels |
|----------|---------|----------|
| Group invites | On | In-app, Push |
| Mentions | On | In-app, Push |
| Session invites | On | In-app, Push |
| Review requests | On | In-app |
| Weekly digest | Off | Email |
| Challenge updates | On | In-app |

### Implementation
- `notifications` table (RLS: user_id)
- Service worker handles push when app closed
- Vercel cron job for daily/weekly digests

## 11. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| WebRTC complexity | High | High | Start with Supabase Realtime broadcast (simpler); upgrade to WebRTC v1.3 |
| Moderation burden | Medium | High | Automated toxicity filter (Perspective API); user reports; admin tools |
| Privacy concerns | Low | High | Strict opt-in; data minimization; clear ToS; GDPR/CCPA ready |
| Notification spam | Medium | Medium | Smart batching; per-category prefs; frequency caps |
| Scale (Realtime) | Low | Medium | Connection pooling; shard by group; monitor Supabase limits |
