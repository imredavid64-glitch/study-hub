## 1. Personal Knowledge Graph

### Concept Extraction
- **Source**: Notes, flashcards, quiz explanations, AI tutor conversations
- **Method**: NER + relation extraction (spaCy/transformers.js in worker)
- **Entities**: Concepts, formulas, definitions, theorems, people, dates
- **Relations**: `prerequisite_for`, `part_of`, `example_of`, `contradicts`, `analogous_to`

### Graph Storage (Supabase)
```sql
CREATE TABLE concepts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  name TEXT NOT NULL,
  aliases TEXT[],
  subject TEXT,
  mastery FLOAT DEFAULT 0,  -- 0-1
  last_reviewed TIMESTAMPTZ,
  source_refs JSONB,  -- [{type, id, excerpt}]
  embedding VECTOR(384),  -- for semantic search
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE concept_relations (
  from_id UUID REFERENCES concepts(id) ON DELETE CASCADE,
  to_id UUID REFERENCES concepts(id) ON DELETE CASCADE,
  relation_type TEXT CHECK (relation_type IN ('prerequisite','part_of','example','contradicts','analogous')),
  strength FLOAT DEFAULT 1,
  evidence JSONB,
  PRIMARY KEY (from_id, to_id, relation_type)
);
```

### RLS: User owns their graph

### Graph Operations
- **Build** — nightly cron + incremental on new content
- **Query** — "What do I need to understand X?" → topological sort of prerequisites
- **Visualize** — D3 force graph in new "Knowledge Map" tab
- **Export** — GraphML/JSON for Anki/Obsidian

## 2. Adaptive Spaced Repetition (Beyond SM-2)

### Current: SM-2 (fixed intervals per rating)
### Target: FSRS-4.5 / Custom Bayesian Model

### Parameters Per Card (Learned)
| Parameter | Meaning | Initial | Learned From |
|-----------|---------|---------|--------------|
| `difficulty` | Base difficulty | 5.0 | First 10 reviews |
| `stability` | Memory durability | 0.4 | Review history |
| `retrievability` | Current recall prob | — | Computed: `exp(-t/stability)` |

### Training Pipeline
1. **Collect** — Every review: (card_id, rating, elapsed_days, retrievability_before)
2. **Optimize** — Nightly: gradient descent on log-likelihood (PyTorch → ONNX → WASM)
3. **Deploy** — Push params to Supabase; client WASM loads for scheduling

### Client Scheduler (WASM)
```rust
// Compiled to WASM, runs in web worker
fn next_interval(card: CardState, rating: Rating) -> f32 {
    let r = retrievability(card.stability, card.elapsed_days);
    let new_stability = update_stability(card.stability, card.difficulty, r, rating);
    let new_difficulty = update_difficulty(card.difficulty, rating);
    -new_stability * ln(0.9)  // target 90% retrievability
}
```

### Fallback: SM-2 if WASM fails / no data

## 3. Weakness Prediction

### Inputs
- Concept graph mastery scores
- Quiz/mock confusion logs (topic-tagged)
- Session focus quality (self-reported + timer adherence)
- Time since last review per concept

### Model: Gradient Boosted Trees (XGBoost → ONNX)
- **Target**: `P(confused_next_session | history)`
- **Features**: 50+ engineered (recency, frequency, difficulty, subject, time-of-day, streak)
- **Output**: Per-concept risk score (0-1) + top contributing factors

### UI: "At-Risk Radar" (enhanced Exam Radar)
- Heatmap: concepts × days until exam
- Auto-enqueue: top-N risks → today's review queue
- Explanation: "You missed 3/5 questions on *redox reactions* last week; mastery dropped to 0.32"

## 4. Study Efficiency Scoring

### Per-Session Metrics
| Metric | Source | Weight |
|--------|--------|--------|
| **Focus Ratio** | Timer active / total time | 0.25 |
| **Recall Success** | Cards rated Good/Easy / total | 0.30 |
| **Confusion Delta** | Pre-session - post-session confusion | 0.20 |
| **Plan Adherence** | Planned tasks completed / planned | 0.15 |
| **Cognitive Load** | Self-report (1-5) inverse | 0.10 |

### Efficiency Score = weighted sum (0-100)
- **Calibration**: Personal baseline (first 20 sessions)
- **Trend**: 7-day rolling average
- **Insights**: "Your focus drops after 45min → try 25/5 cycles"

## 5. Advanced AI Tutor

### Multi-Modal Input
| Modality | Implementation |
|----------|----------------|
| **Text** | Existing chat |
| **Image** | `input type=file accept=image/*` → base64 → vision model (LLaVA via Groq) |
| **Audio** | Web Audio API → MediaRecorder → Whisper (Groq) → text |
| **PDF** | pdf.js extract → chunk → embed → RAG |

### Socratic Mode (Toggle)
- **System Prompt**: "Never give answers. Ask guiding questions. Confirm understanding before proceeding."
- **Behavior**: Decompose problem → ask for first step → validate → next step
- **Exit**: "Give me the answer" button (logs as "socratic_exit")

### Exam Simulation
1. **Config**: Subject, duration, question types, difficulty mix
2. **Generate** — AI creates full exam (MCQ, FRQ, derivations)
3. **Take** — Timed, locked interface (no tab switch)
4. **Grade** — AI grades FRQs with rubric; explains each deduction
5. **Report** — Per-topic score, time allocation, confusion tags → auto-enqueue

### Learning Style Adaptation
- **Detect**: From note styles, explanation preferences, media consumption
- **Adapt**:
  - Visual → more diagrams, mind maps
  - Verbal → longer explanations, analogies
  - Active → more problems, fewer readings
  - Sequential → step-by-step; Global → overview first

## 6. Predictive Analytics

### Grade Trajectory (Monte Carlo)
```python
def simulate_grade(current_state, days_until_exam, n=10000):
    trajectories = []
    for _ in range(n):
        mastery = current_state.mastery.copy()
        for day in range(days_until_exam):
            study_hours = sample_from_user_distribution(day)
            mastery = decay_and_review(mastery, study_hours)
        trajectories.append(exam_score_model(mastery))
    return {
        'mean': np.mean(trajectories),
        'p10': np.percentile(trajectories, 10),
        'p90': np.percentile(trajectories, 90),
        'grade_dist': histogram(trajectories)
    }
```

### Intervention Alerts
- **Trigger**: `P(target_grade) < 0.3` AND `days_until_exam < 14`
- **Action**: Generate catch-up plan (which concepts, how many hours, suggested schedule)
- **Delivery**: In-app banner + push + email (if opted in)

### Capacity Planning
- **Input**: Available hours/week (user-set), current mastery, exam dates
- **Optimizer**: Linear programming → maximize `Σ P(pass_exam_i)`
- **Output**: "Allocate 4h Chem, 3h Math, 2h review this week"

## 8. Offline-First Architecture

### Local ML (WASM)
- Scheduler (FSRS) — 50KB WASM
- Grade trajectory (simplified) — 30KB WASM
- Concept embeddings — ONNX Runtime Web (quantized, ~2MB)

### Sync Strategy
- **Local writes** → `localStorage` + IndexedDB (large blobs)
- **Background sync** — Service worker pushes to Supabase when online
- **Conflict resolution** — Last-write-wins for params; merge for graph (union of edges)

### Progressive Enhancement
| Feature | Offline | Online |
|---------|---------|--------|
| FSRS Scheduling | ✅ WASM | ✅ + server retrain |
| Knowledge Graph | ✅ Local build | ✅ + semantic search |
| Weakness Prediction | ❌ | ✅ |

## 12. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| WASM bundle size | Code-split; load on demand; fallback to JS |
| Model drift | Weekly retrain cron; monitor prediction calibration |
| Privacy (graph) | Never leaves device unless cloud sync enabled; encrypt at rest |
| Compute cost (MC) | Run in Vercel Edge Functions (10s limit); cache results 1hr |
| False positives (weakness) | Conservative threshold; user can dismiss; track dismissal rate |
